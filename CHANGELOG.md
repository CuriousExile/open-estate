## [Unreleased]

### Added

- Specification of the duplicate detection (`.kiro/specs/duplicate-detection/`): requirements, design and implementation plan.
- Optional Objektmerkmale in the listing model: `address.houseNumber`, `address.unit`, `floor`, `totalFloors`, `yearBuilt`, `plotArea`, `bedrooms`, `bathrooms` and `parcelId`. Every field is optional, so each existing listing stays valid and keeps its Inhalts_Hash; `taxonomy.json` decides per property group which of them may be used, and merkmale a group does not allow are dropped and named (`droppedFields`, run log).
- Pure duplicate matching logic in `@open-estate/shared` (`duplicates/`): normalization of addresses and texts, Merkmalsprofil with SimHash signatures and hashed identifiers, the rule-based Duplikat_Bewertung with exclusions, Ortsanker and configurable weights (`duplicate-detection.json`), and the Blockschlüssel of the candidate search.
- Markierungen (`flags.ts`) with the `DUPLICATE` code, the permission `duplicate:review` and the error code `IDEMPOTENCY_KEY_REUSED`.
- Duplicate detection on every write, on every channel (portal, machine access, admin mode, connectors): `DuplicateDetector` and the `DuplicateIndex` table in `core`, kept in step by the `VersionedListingWriter`. A listing created as a duplicate of an older listing of the same agency is stored `INACTIVE` with a `DUPLICATE` flag (version 1 records `statusReason`); activating it (`PUT /listings/{id}/status`) or dismissing the flag (`DELETE /listings/{id}/flags/DUPLICATE`) records that the pair is not a duplicate. Edits, restores, agency assignments and imports only set, update or remove the flag, never the status. `GET /listings?flag=DUPLICATE`, `flags`/`flagCodes`/`createdAt` in the responses, audit actions `listing.flag.*`, metric `listing.duplicate_flags`; connector runs count such listings as `flagged`.
- `Idempotency-Key` header on `POST /listings`: a repeated creation by the same actor with the same body within 24 hours returns the listing created first (`Idempotent-Replayed: true`), another body is `409 IDEMPOTENCY_KEY_REUSED` (table `IdempotencyKeys`, TTL 24 h).
- Daily duplicate check (`DuplicateSweep` state machine, Lambda and EventBridge schedule at `sweep.timeUtc`, default 03:00 UTC, alarm on failed or timed-out runs): rebuilds the duplicate index from the stored listings (also after rule changes or writes outside the write paths), renews every flag (`detectedBy: SWEEP`), removes the data of listings that no longer exist and records duplicates across agencies as reports (`DuplicateReports` table) without touching the listings. Start on demand with `POST /platform/duplicate-sweeps`.
- Reports of duplicates across agencies for platform admins (`duplicate:review`): `GET /platform/duplicate-reports`, `POST /platform/duplicate-reports/{reportId}/dismiss`, metric `duplicate.cross_agency_open`; admin mode view "Duplicates across agencies".
- Agency portal: property attributes in the listing form (only those of the selected type's group), a "possible duplicate" badge and flag filter in the listing overview, the duplicate notice with "Activate anyway" (with confirmation) and "Dismiss flag" in the workspace, a notice after creating a duplicate, and "automatically deactivated" in the version history. The public detail view shows stored property attributes. `/meta` lists the attributes per property group.
- Deletion requests also remove a listing's duplicate index entries, its reports across agencies and its `Idempotency-Key` records.
- On/off switch of the duplicate detection for cost control: CDK context `duplicateDetection` (`enabled` by default, `disabled` starts without it) sets the new SSM parameter `/open-estate/<env>/duplicate-detection`; platform admins switch it at runtime in the admin mode (Operations → Duplicate detection) or with `GET`/`PUT /platform/duplicate-detection`, locally with `DEV_DUPLICATE_DETECTION=disabled`. Switched off, creations, changes, imports and the seed are stored without check, flag or duplicate index writes, the daily check ends right after its start (`SKIPPED`) and `POST /platform/duplicate-sweeps` answers `409 DUPLICATE_DETECTION_DISABLED`; existing flags and reports stay and can still be released or dismissed. Switching it on starts a duplicate check that rebuilds the index and renews every flag. Changes apply within 60 seconds without reload.
- Demo data: property attributes, a duplicate, a flat in the same building that is no duplicate and the same flat at another agency (local demo and `npm run seed`); load test bodies and a k6 script for the creation latency with 200 candidates (`packages/loadtest`).
- Project specification: requirements, design and implementation plan.
- Open-source project scaffolding: license, roadmap, contribution guidelines, code of conduct, security policy, issue and PR templates.
- Test tiers and areas: `npm test` is a quick tier (no `infra`, property tests capped at 10 runs), `npm run test:full` runs everything (CI), `npm run test:<area>` runs one functional area, `npm run verify` is the final check. `AGENTS.md` for AI coding agents.
- Playwright browser tests (`packages/browser-tests`, `npm run test:browser`) against the local demo on their own ports, part of `./run-everything.sh` (`SKIP` without a Chromium): public search (105 tests, desktop and a phone viewport), agency portal (58) and admin mode (32). State-changing tests run one at a time on a freshly reset demo. Bugs they found are listed in its README.
- Activating and deactivating listings (Req 6.2) in the portal: in the listing overview (per row) and in the workspace header; in admin mode for the listings of every agency. Signed-in agency users (their own listings) and platform admins (all) manage listings right from the public search: *Deactivate* / *Activate* and *Edit* on the result cards, and a *Manage this listing* bar above the listing detail (also on `/listings/{id}`); anonymous visitors cause no additional requests.
- Management API: `GET /listings?ids=<id>,…` looks up 1 to 50 listings at once (e.g. a page of search results) and returns those the caller may read; unknown ids and other agencies' listings are left out. The public search uses it once per result page for signed-in users.
- Local demo: `DEV_TEST_HOOKS=1` enables `POST /__test__/reset` (DEV ONLY), which replaces all state with a fresh seed.
- Local demo ports are configurable: `DEV_PORT` (dev server, default 4310) and the new `DEV_FRONTEND_PORT` (`ng serve`, default 4200), so a second demo (e.g. for browser tests) can run next to one on the default ports. The dev server now generates the SPA's local `runtime-config.json` with its own OIDC issuer, and the `ng serve` proxy (`dev/proxy.local.mjs`, was `proxy.local.json`) reads the same variables; `npm run dev` validates them up front.
- `./run-everything.sh`: one command that installs, lints, type-checks, builds, runs all tests, synthesizes the CDK stacks and smoke-tests the local demo, with a PASS/FAIL/SKIP summary; fetches the pinned Node.js if needed.

### Changed

- Creating a listing that duplicates an older listing of the same agency no longer publishes it: it is stored `INACTIVE` with a `DUPLICATE` flag even if `ACTIVE` was requested (listing-management Req 4.2, 12.5). Integrations that relied on creating identical listings as independent active listings must release them.
- Writes of listings are also conditioned on the stored flags and the duplicate index profile, so a concurrent dismissal or duplicate check is never undone; a write that loses such a race answers `409 VERSION_CONFLICT` with the unchanged version.
- `ActorRef` has a new kind `system` (`{"kind": "system", "job": "duplicate-sweep", "runId"}`) for audit entries of the daily duplicate check.

### Fixed

- Admin mode → Operations was unusable: an empty modal dialog covered the page on load (the template's safe navigation yields `null`, which the confirmation dialog took for a confirmation).
- Admin mode → Platform monitoring: the agency activity failed with "Some entries are invalid" for every period but 30 days (a daily metric was requested per hour); it is now always requested per day. The period and access-mode dropdowns showed their first option instead of the active one.
- Version history: "Portal ·User …" is "Portal · User …" again.
- Refused requests of users and machine accesses of a suspended agency are audited with the identified actor and agency (Req 2.8); before, the entry had no actor.
- Search results or a listing opened from them sometimes did not appear until the next mouse move or key press: the search page's `@defer` blocks waited for browser idle time, which a busy browser can withhold for seconds. They now render `on immediate` (still lazy chunks); a slow detail chunk shows "Loading listing …".
- Image carousel: `NG0950` (required input read too early) when a carousel appeared under a resting pointer; events before its first render are ignored now.
- `npm run seed` and the load-test generator (`packages/loadtest`, `--env`) wrote raw listing items without management attributes (status, version, field origins): the Management API could not read them and the duplicate check skipped them as `invalid`. Both now import through the connectors' pipeline (`createImportPipeline` in `@open-estate/ingestion`, mode `REPLACE`), so seed data gets versions, counters, snapshots and the duplicate check; the seed's repost `seed-de-berlin-010` is stored `INACTIVE` with a `DUPLICATE` flag. They read the stores from the outputs of the `Data` and `ManagementData` stacks (new outputs `DeletionBlocklistTableName`, `ListingVersionsTableName`, `ListingKeysTableName`, `MetricCountersTableName`, `DuplicateIndexTableName`, `SnapshotBucketName`) and the configuration from the deployed config bucket; `--table` is replaced by the connector Lambda's variables, `--concurrency` is new.
- `POST /platform/reload` and `open-estate-admin reload` did not restart the Management API, so changed taxonomy, allowlists or `duplicate-detection.json` reached portal and machine accesses only with a cold start. `POST /platform/reload` now restarts the Management API as well (last), and the new `ReloadFunctionNames` output of the Management stack lists it for the CLI; administrators need the new managed policy `ReloadPolicyArn` of that stack in addition to `AdministratorPolicyArn`.
- `listing arbitraries` test failed in about a third of quick-tier runs: it checked that generated listings cover every offer-type combination, but the quick tier caps property runs at 10. The coverage check now uses a fixed-seed sample.
- Dry run of removing a Plattform_Admin could answer `LAST_PLATFORM_ADMIN` for an admin that a concurrent request had just removed; it now re-reads the membership (fast-check seed 713905340).

- `tsc -b` failed on a fresh checkout because `tsconfig.tsbuildinfo` files were committed without their `dist/`; build info now lives in `dist/` and is git-ignored.

### Changed

- Node.js `engines` set to `^22.12.0 || >=24.0.0` (was `>=20.19.0`, which the Angular CLI never supported); `.nvmrc` pins 22.21.0, the version the checks are tested with.
- Frontend on Angular 21.2 (was 22.2) and TypeScript 5.9 (was 6.0): Angular 22 refuses Node below 22.22.3, and Angular 21 needs TypeScript < 6.0. Templates no longer read `private` members.
- Every dependency pinned to a release at least four weeks old and the lockfile regenerated with `npm install --before=2026-10-10`, so `npm ci` works from registry mirrors that lack recent versions.
- Angular pinned to 21.2.24 (was 21.2.25, CLI/build 21.2.26) and the AWS SDK clients and `lib-dynamodb` to 3.1142.0 (was 3.1149.0): the registry serves no tarballs for 18 of the locked versions, so `npm ci` failed. 21.2.24 and 3.1142.0 are the newest versions available for every package of each family; both predate 2026-10-10.
